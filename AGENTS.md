# AGENTS.md

## What is this project

`crab_cpp` is a header/module-only C++23 library that brings Rust-like types and
ergonomics to modern C++:

- `panic!` and `unimplemented!` (see `panic.cppm`)
- `Option<T>` (see `option.cppm`)
- `Result<T, E>` (see `result.cppm`)
- a `match` pattern-matching macro (see `match.cppm` / `include/crab_cpp/macros.h`)
- an optional UTF-8 `Char` / `str` / `String` sub-module (see `string.cppm`)

Everything is packaged as C++20 modules and only supports C++23 with
`import std;`. The top-level module `crab_cpp` re-exports the sub-modules from
`src/mod.cppm`.

Builds are provided for both CMake (`CMakeLists.txt`) and xmake (`xmake.lua`).
Tests live in `tests/` and use GoogleTest.

## Ground rules

- Follow @.agents/codeStyle.md strictly. It reflects the style
  already used in `src/`, which is the source of truth.
- Match the conventions of surrounding code when in doubt.
- Keep changes scoped; do not reformat unrelated code.
- New public types belong in namespace `crab_cpp` (or a documented sub-namespace
  such as `crab_cpp::raw`, `crab_cpp::strings`, `crab_cpp::literal`).
- Prefer adding Doxygen `@brief` comments to new public API, as the rest of the
  codebase does.

## clangd / editor setup

VSCode uses clangd (see `.vscode/settings.json`), which reads
`compile_commands.json` and the prebuilt module files from
`cmake-build-debug-clang++`:

- `--compile-commands-dir=${workspaceFolder}/cmake-build-debug-clang++`

These files are generated by CMake/clang++ and go stale whenever a module is
added, removed or renamed, or when a sub-module's exports change. Refresh them
with:

```sh
# Regenerate compile_commands.json
cmake -S . -B cmake-build-debug-clang++

# Rebuild the module .pcm files
cmake --build cmake-build-debug-clang++ --target crab_cpp
```

**The `.pcm` rebuild can fail while clangd is running.** clangd memory-maps the
existing `.pcm` files, so clang++ cannot overwrite them and reports:

```
error: unable to open output file '...\crab_cpp-*.pcm': 'The requested
operation cannot be performed on a file with a user-mapped section open.'
```

So when adding/removing a module, or otherwise changing module interfaces:

1. Close VSCode (or stop the clangd server) to release the `.pcm` files.
2. Reconfigure and build as shown above.
3. Reopen VSCode, so clangd picks up the new `compile_commands.json` and modules.
